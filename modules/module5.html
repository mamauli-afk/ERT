Модуль 5. Работа с объектами базы данных через визуальный редактор

Цель

Освоить создание и изменение основных объектов БД без написания DDL-скриптов вручную.

Прогресс модуля 0 из 5 (0%)
Краткий теоретический блок

Визуальный редактор объектов

Red Expert предоставляет визуальный редактор для всех основных объектов базы данных. Создавать и изменять их можно через формы, без ручного написания DDL-скриптов:

Таблицы Индексы Генераторы Процедуры Триггеры Представления Домены Исключения Роли

При сохранении объекта Red Expert сам формирует соответствующий DDL-скрипт и выполняет его на сервере. Этот скрипт можно посмотреть и сохранить — он пригодится в отчёте и итоговом проекте.

Создание объекта и его изменение (ALTER)

  • Создание (CREATE) — объект появляется в базе данных впервые. Задаются все его свойства: поля, типы, ключи, индексы и т.д.
  • Изменение (ALTER) — меняются свойства уже существующего объекта: добавляются или удаляются поля, меняются типы, добавляются внешние ключи, индексы и триггеры.

В визуальном редакторе Red Expert создание и изменение выполняются в одной и той же форме: для нового объекта вы открываете диалог создания, для существующего — диалог редактирования. Разница в том, какой DDL-скрипт сгенерируется: CREATE или ALTER.

Совет. Всегда сохраняйте сгенерированный DDL-скрипт после каждого изменения. Это пригодится при сравнении схем, откате изменений и подготовке итогового проекта.

Задание 1. Создание таблицы

Создайте таблицу STUDENT с полями: ID (целое, PK), NAME (varchar), BIRTH_DATE (date). Используйте визуальный редактор, а затем сгенерируйте DDL-скрипт и сохраните его в тетради.

Подсказка: в дереве подключений щёлкните правой кнопкой по узлу «Таблицы» → Создать таблицу. После сохранения откройте вкладку с DDL-скриптом (кнопка Показать DDL или аналогичная) и скопируйте его в поле ниже.

Задание 2. Изменение таблицы

Добавьте в созданную таблицу поле EMAIL и внешний ключ на таблицу GROUP. Зафиксируйте изменения.

Если таблицы GROUP в учебной БД нет, создайте её минимально (поля ID и GROUP_NAME) или используйте существующую таблицу групп. Внешний ключ должен ссылаться на её первичный ключ.

Задание 3. Создание индекса

Создайте индекс по полю NAME. Сравните время выполнения запроса SELECT * FROM STUDENT WHERE NAME = '...' до и после создания индекса.

Время выполнения отображается в панели «Вывод» после запуска запроса. Для чистоты эксперимента выполните запрос 2–3 раза до и после создания индекса и зафиксируйте типичное значение.

Задание 4. Создание триггера

Создайте простой триггер BEFORE INSERT, который автоматически заполняет поле CREATED_AT текущей датой.

Если поля CREATED_AT в таблице STUDENT ещё нет — сначала добавьте его через визуальный редактор (тип TIMESTAMP или DATE), затем создавайте триггер.

Задание 5. Создание хранимой процедуры

Напишите процедуру, возвращающую количество студентов в заданной группе. Выполните её через компонент выполнения хранимых процедур.

Подсказка: для Firebird процедура может выглядеть так — CREATE PROCEDURE STUDENTS_IN_GROUP (GRP_ID INTEGER) RETURNS (CNT INTEGER) AS BEGIN SELECT COUNT(*) FROM STUDENT WHERE GROUP_ID = :GRP_ID INTO :CNT; SUSPEND; END. Адаптируйте под фактические поля вашей таблицы.

  • Понимаю разницу между CREATE и ALTER.
  • Умею добавлять поля и внешние ключи в существующую таблицу.
  • Знаю, как создать индекс и как оценить его эффект по времени выполнения.
  • Умею создавать триггер BEFORE INSERT и проверять его работу.
  • Умею создавать и выполнять хранимую процедуру.
