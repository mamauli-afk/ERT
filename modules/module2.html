Модуль 2. Подключение к базе данных и создание подключения

Цель

Научиться устанавливать соединение с существующей базой данных и создавать новую.

Прогресс модуля 0 из 3 (0%)
Краткий теоретический блок

Параметры подключения

  • Сервер — хост и порт, на котором работает Firebird / Ред База Данных (например, localhost:3050).
  • Путь к файлу базы данных — полный путь к .fdb на сервере (например, C:\DB\phonebook.fdb или /var/lib/firebird/phonebook.fdb).
  • Пользователь и пароль — учётные данные СУБД (по умолчанию SYSDBA / masterkey, но в учебной БД пароль может быть изменён).
  • Кодировка — например, UTF8 или WIN1251; должна совпадать с кодировкой базы данных.
  • Драйвер JDBC — библиотека jaybird, через которую Red Expert взаимодействует с Firebird.

Одновременная работа с несколькими подключениями

Red Expert позволяет держать открытыми несколько подключений к разным базам данных одновременно. Переключение между ними выполняется в дереве подключений; для каждого подключения открывается своя рабочая область.

Расширенные параметры

  • SSH-туннель — позволяет подключаться к удалённому серверу Firebird через SSH-соединение без прямого доступа к порту СУБД.
  • Шифрование сетевого соединения — настройки TLS/SSL для защиты передаваемых данных.
Совет. Перед созданием подключения убедитесь, что сервер Firebird запущен, а путь к файлу БД указан именно с точки зрения сервера (не клиента). Типичная ошибка новичка — указать локальный путь вместо серверного.

📦 Подготовка учебной базы данных «Телефонный справочник»

Все задания модулей 2–8 выполняются на единой учебной базе данных «Телефонный справочник». Чтобы приступить к работе, скачайте скрипт создания БД и выполните его в Red Expert — скрипт создаст все нужные таблицы, представления, триггеры, процедуры, роли и тестовые данные.

⬇ Скачать скрипт phonebook.sql Содержит 5 таблиц (CITY, CLIENT, PHONE, PHONE_TYPE, CONTACT_GROUP), 4 процедуры, 3 представления, 6 триггеров, 2 роли и тестовые данные (15 клиентов, 26 телефонов). Формат — SQL-текст, кодировка UTF-8.

Как выполнить скрипт в Red Expert

  1. Создайте базу данных. В Red Expert: База данных → Создать. Укажите путь к файлу phonebook.fdb, кодировку UTF8, пользователя SYSDBA и пароль 5
  2. Откройте SQL-редактор для этого подключения (правой кнопкой по подключению → SQL-редактор, либо через панель инструментов).
  3. Вставьте весь скрипт целиком в редактор: откройте скачанный phonebook.sql любым текстовым редактором (Notepad, VS Code), скопируйте всё содержимое и вставьте в Red Expert.
  4. Выполните как скрипт. Используйте кнопку Выполнить скрипт (Execute Script) или соответствующее сочетание из меню — а не просто Выполнить запрос. Так корректно обработаются блоки SET TERM ^ ; в процедурах и триггерах.
  5. Проверьте результат. Выполните запрос: SELECT * FROM CLIENT ORDER BY LAST_NAME; — должно вернуться 15 строк.
Важно: строка CONNECT в начале скрипта. В некоторых версиях скрипта первая строка содержит команду вида CONNECT 'localhost/3050:C:/Users/.../PHONEBOOK.FDB' USER 'sysdba' PASSWORD '...'. Эта строка содержит путь и пароль с компьютера, где скрипт создавался, и на вашем компьютере вызовет ошибку.

Что делать: откройте файл в текстовом редакторе, найдите строку, начинающуюся с CONNECT, и либо удалите её целиком, либо закомментируйте, поставив в начале --. Скрипт будет выполняться в том подключении, которое уже открыто в Red Expert, и строка CONNECT ему не нужна.
Если при выполнении возникла ошибка триггера «BU_CLIENT». В экспортированных скриптах иногда встречается ситуация, когда триггер сначала создаётся как BEFORE INSERT (пустая заглушка), а затем переопределяется как BEFORE UPDATE. Firebird в некоторых версиях не позволяет менять тип триггера через CREATE OR ALTER. Если увидели ошибку — выполните вручную:

DROP TRIGGER BU_CLIENT;
а затем повторно запустите скрипт с шага 4. Все остальные объекты уже будут созданы и повторно не продублируются благодаря CREATE OR ALTER.
Проверка после выполнения. В дереве подключений должны появиться все типы объектов: таблицы, представления, процедуры, триггеры, индексы, домены, генераторы (sequences), исключения, роли. Это и есть материал для задания 1 (изучение дерева подключений) и всех последующих модулей.

Если скрипт уже выполнен ранее и база данных существует — повторно запускать его не нужно, сразу переходите к заданиям. Для чистой переустановки создайте новый файл .fdb или выполните DROP-команды из раздела 12 скрипта.
